# Question rules

Every question must pass these checks before it is shown.

## Format (always)

Every question is multiple choice with four options A–D and exactly one correct. No open-ended or multi-part questions. For output and SQL questions, give four possible outputs as the options. Never print answers or working in the test.

## What makes a good question

- It tests one clear idea and has realistic numbers.
- Every wrong option comes from a real mistake, not a random value.
- All four options are different, in the same format, and only one is correct.
- All assumptions are stated.

## Checks by section

| Section | Check |
| --- | --- |
| Quant | Compute the answer and every option with code. Only one option may match. |
| Logical puzzles | Enumerate every arrangement or set model with code. Exactly one answer must survive. |
| Series, coding-decoding | Generate with code. No other simple rule may lead to a different option. |
| Verbal | One option must be clearly best, with a reason each other option is wrong. Write original passages. |
| C / Java output | Run the program. Avoid undefined behaviour unless the answer is "undefined behaviour", and avoid implementation-defined output. |
| SQL | Run the query on a scratch database. |
| OS, networks, OOP | The answer must be a settled fact. Check that no option is also true under another reading. If behaviour differs by language, name the language. |

## If code can't be run

Solve by two different methods, or list every case for puzzles. Limit questions to behaviour you are certain of. Tell the student the key was not executed. If you are not certain, discard the question and write a different one.
